# ADR-002: Выбор среды исполнения доменных расчётов (TypeScript Port vs Pyodide vs Python API)

- **Статус:** Принято (Accepted)
- **Дата:** 2026-10-26
- **Контекст:** Этап 0 технического спайка SonoForge Web (Спецификация §4, §5.1, Этап 0)

---

## 1. Контекст и проблема

Ключевое требование SonoForge Web — 100% численная эквивалентность доменных эхокардиографических формул с настольным Python-приложением `areatu/SonoForge` при соблюдении локальной приватности (без обязательной отправки данных на сервер), быстрого холодного старта (`< 2 с`) и минимального потребления памяти в браузере.

Рассмотрены три варианта исполнения расчётного ядра:
- **Вариант R1 — Прямой порт расчётного ядра на чистый TypeScript** (`packages/domain`, прототип `spike/domain-ts/`) с автоматическим дифференциальным тестированием по golden-векторам, генерируемым непосредственно из Python-кода `SonoForge`.
- **Вариант R2 — Исполнение оригинального Python-кода в браузере через Pyodide (`CPython 3.12 WASM`)**.
- **Вариант R3 — Вызов серверного Python API** для выполнения расчётов.

---

## 2. Эмпирические данные сравнения (`R1` vs `R2` vs `R3`)

Эксперимент с `pyodide@0.27.5` выполнен скриптом `spike/scripts/eval_pyodide.mjs` (`npm run spike:bench-pyodide`, отчёт `docs/spike/results/pyodide_eval.json`).

| Критерий | R1: Чистый TypeScript (`spike/domain-ts`) | R2: Pyodide `0.27.5` (WASM) | R3: Серверный Python API |
|---|---:|---:|---|
| Размер бандла расчётного ядра (gzip) | **3.2 KiB** (`8.3 KiB` raw) | **5,652 KiB (5.52 MiB)** только ядро CPython + **~25–30 MiB** колёса `numpy`/`scipy` | 0 KiB на клиенте, но требует постоянный сервер |
| Холодный старт рантайма (локальный диск, без сети) | **< 1 ms** (нативный V8/JSC/SpiderMonkey) | **1,469.8 ms** (инициализация CPython WASM без загрузки колёс по сети) | Зависит от RTT сети; ломает offline/local-first |
| Прирост памяти (RSS / WASM Heap) | **< 0.5 MiB** | **+83.8 MiB RSS** (начальная линейная куча WASM `20.0 MiB`) | На сервере |
| Латентность 1 000 вызовов (`BSA + Teichholz + LVM + RWT`) | **1.925 ms** (`1.925 µs/вызов`) | **10.23 ms** (`10.23 µs/вызов`, в **5.3× медленнее** из-за JS↔WASM FFI) | `20–150 ms` на сетевой запрос |
| Совместимость `echo_personal_tool.domain` «из коробки» | Полная типобезопасность (`strict: true`) | **Падает при пакетном импорте:** `calculations/__init__.py` жадно импортирует `numpy` и `scipy.interpolate` | Высокая, но нарушает local-first |
| Многопоточность и нативные колёса | Нативные Web Workers | `Thread.start()` выбрасывает `RuntimeError: can't start new thread`; нет колёс `pylibjpeg-openjpeg`, `pyjpegls`, `onnxruntime` | Серверная |
| Приватность и работа без сервера | **100% в браузере (Zero-Server Ready)** | 100% после кеширования ~35 MiB WASM-ассетов | Требует передачу параметров/сессии по сети |

---

## 3. Решение

Принят **Вариант R1**: **чистый порт расчётного ядра на TypeScript (`packages/domain`)** без зависимостей от UI, DOM, DICOM-парсеров и сторонних математических библиотек, сопровождаемый обязательным автоматическим набором дифференциальных golden-тестов против эталонного Python-репозитория `SonoForge`.

### Почему отклонён Pyodide (`R2`)
1. **Неоправданный вес в 1 700× больше:** базовые формулы ЭхоКГ — это компактная аналитическая геометрия и алгебра (`3.2 KiB` gzip на TypeScript против `5.52 MiB` ядра Pyodide + `25–30 MiB` `numpy`/`scipy` из-за жадного `calculations/__init__.py`).
2. **Бюджет холодного старта и памяти:** добавление `+83.8 MiB` памяти и `~1.5 с` CPU-инициализации (плюс скачивание десятков мегабайт по сети при первом визите) напрямую ухудшает целевой бюджет `< 2 с` до интерактивной оболочки, особенно на планшетах и рабочих станциях со слабым каналом.
3. **Архитектурные ограничения Emscripten:** отсутствие стандартных потоков Python и нативных DICOM-декодеров (`openjpeg`, `charls`) всё равно требует реализации DICOM-конвейера на JS/WASM вне Pyodide.

### Почему отклонён серверный Python API (`R3`) как основной рантайм
Нарушает ключевой принцип **local-first / zero-upload** при работе с локальными DICOM-файлами и делает невозможным мгновенный (`60 fps`) интерактивный пересчёт объёмов и хорд Симпсона при перетаскивании узлов контура мышью.

## 4. Механизм защиты от расхождения формул (Differential Golden Pipeline)

1. Скрипт `spike/scripts/generate_golden_vectors.py` импортирует модули настольного `SonoForge` (с фиксацией `git commit SHA` в JSON-шапке) и генерирует `tests/golden/domain_vectors_v1.json` (нормальные клинические сценарии, педиатрические/экстремальные значения, граничные и невалидные входы `0`, `-1`, `LVESD >= LVEDD`, `ESV > EDV`, отсутствие `BSA` и калибровки).
2. Набор `tests/domain_differential.test.ts` запускается при каждом коммите в CI за `< 30 ms` и блокирует слияние при любом расхождении сверх строгих допусков `PARITY_CATALOG.md`.
3. Тест `tests/architecture_purity.test.ts` механически запрещает любые импорты React, DOM, `window`, `document`, `dicom-parser` или кодеков внутрь `domain-ts`.
